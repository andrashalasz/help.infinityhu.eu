9.5 UNASFull page

A screen for managing UNAS webshops, where you can specify which webshops you work with, which warehouses you use and which products you sell. Available functions:

  • Managing an unlimited number of webshops in parallel

  • Uploading products

  • Immediate, automatic refresh of stock changes

  • Electronic invoicing at the press of a button, or automatically

  • Immediate settlement of invoices belonging to cash and card orders

9.5.1UNAS API keys

A new webshop can be added with Add new (a name, a description and an API key are required). Only API keys with active status are synchronised.

Conditions for UNAS to run:

  • An invoice-issuing company must exist

  • Among the sites of the invoice issuer, at least one must be a main site

  • The main site must have a normal customer invoice block

  • There must be at least one active API key

  • The background processes must be set up correctly

9.5.2UNAS order log

Clicking the Run download process button downloads the orders with invoiceable status from the webshop. Based on the order identifier, the system checks that anything already invoiced is not downloaded again.

During order synchronisation the following data are generated: partners, addresses, contact details, products, VAT rates, financial transactions, sales, invoices.

If the run status of the order log is not Completed but Failed or Waiting, open the log for the error message. In case of an error, click the download button next to the key on the UNAS API keys screen — this immediately downloads every order that has not been downloaded.

9.5.3Partner synchronisation

Partners are only downloaded when the order is generated. A new partner is created based on an e-mail address check. If the e-mail already exists in the system, only the billing and address data are refreshed (this does not affect invoices issued earlier).

For a partner with a tax number, the system takes over the tax number in an unchanged format (the validation is performed when the invoice is issued). If the tax number is incorrect, an open sale is created when the order is downloaded, and an error message indicates the problem when the invoice is opened.

9.5.4Product synchronisation – object links

Basic conditions of synchronisation:

  • The background process must be active

  • The product must have an item number, a name, a category, a selling price and a product image

  • One of the above has to change (synchronisation is triggered by a change)

On the UNAS object links → Product screen you can define, from the product master data, what is published to the webshop. The left and right columns can be linked; the items linked with the API key appear on the given website. One product can be linked to several API keys.

The Add link button finalises the link and the Remove button deletes it. The Last refreshed field shows the date of the most recent synchronisation.

For the first time, or for a campaign-like refresh, you can use the Synchronise all button (it performs the synchronisation even without a change).

⚠ Caution

In the information bar you can continuously check which product's list price expires within 5 days. Expiring prices have to be modified or extended, because UNAS treats items without a price as erroneous.

Product images are synchronised as well, but UNAS only takes over the image if no image has been uploaded for the item on the website yet.

9.5.5Category synchronisation

When managing products, the categories linked to the product are generated in the webshop as well (with the full path). This menu serves exclusively for synchronising categories that are not linked to a product.

9.5.6Warehouse synchronisation

Here you specify which warehouse's stock the webshop uses. Stock synchronisation only runs for items that have already been created.

ℹ Note

Both the warehouse and the item have to be linked with the active API key. By default, synchronisation is only triggered by a stock movement; with the Full sync button the stock can be refreshed even without a warehouse movement.

9.5.7UNAS synchronisation log

Used to check the running of the background synchronisation procedure. In case of an error, here you can see for which products and warehouses the synchronisation did not run and what the reason was. After the correction, the background process runs again automatically.

9.5.8Settling UNAS invoices

Automatic settlement is possible for both cash and card invoices (when the invoice is issued, the settlement document is also created and the balance of the invoice becomes zero).

For a cash invoice, only one setting is required. For card invoices, the system only settles automatically if it receives the “Payment successfully completed” status from the UNAS website and the amount matches the amount of the order.
