10.4 SettingsFull page

The Settings menu contains all the master data managers. The submenus are organised into the following groups: Organisational structure, Job and employment, Working time and scheduling, Compensation and benefits, Calendar and time calculation, Onboarding settings.

10.4.1Organisational structure

Menu: Settings → Organisational structure

10.4.1.1Division

Divisions are the top-level units of the organisation. On this basis the departments, positions and employees can be grouped in the reports.

Field Type Mandatory? Explanation / tips
Name of the division Text Yes It appears in the lists and reports.
Colour Selector No It assigns a colour to the division
Group Drop-down No If the given division is a member of a group, it has to be selected here

10.4.1.2Location

Locations serve to keep records of the offices and sites. They can be assigned to positions, employees and work schedules.

Field Type Mandatory? Explanation / tips
Name of the location Text Yes For example Budapest – head office, Dubai office.

10.4.2Job and employment

Menu: Settings → Job and employment

10.4.2.1Job roles

In the system, the job role is the type of the job. It is needed so that the classification of the positions and the employees is consistent, and so that we get comparable data in the reports later.

Creating a job role:

  1. Open: Settings → Job and employment → Job roles.

  2. Click: Create.

  3. Enter the name of the job role (for example “IT Support”).

  4. Choose a colour for the job role

  5. Save.

Field Type Mandatory? Explanation / tips
Name of the job role Text Yes This is what will be visible in the lists and reports.
Colour Selector No It assigns a colour to the job role

10.4.2.2Seniority level

The seniority levels (for example junior, medior, senior, lead) record the levels within the job roles. They can be used as a filtering dimension for positions and in recruitment as well.

Field Type Mandatory? Explanation / tips
Name of the level Text Yes For example junior, medior, senior, lead.
Active Switch No

10.4.2.3Type of employment

The type of employment determines the nature of the employment relationship.

Field Type Mandatory? Explanation / tips
Name of the type Text Yes For example full-time, part-time, contractor.
Active Switch Yes An inactive type does not appear when a new person is hired.

10.4.2.4Working mode

The master data of the working mode: the way of working that can be assigned to positions and employees

Field Type Mandatory? Explanation / tips
Name of the mode Text Yes For example office, hybrid, remote.
Active Switch Yes An inactive mode cannot be selected for a new record.

10.4.6Onboarding settings

Menu: Settings → Onboarding settings

This submenu contains the configurable elements of the onboarding and recruitment process.

10.4.6.1Creating the employee data sheet

When a new employee is being hired, a data request link has to be sent out on this screen. The e-mail address of the new employee, the language of the communication and the language of the system to be used have to be entered.

The system sends the link to the employee.

Clicking the link opens the data request screen.

The employee fills in the requested data, attaches their employment documents, and the Infinity administrator converts them into an employee in the system on the basis of the completed data sheet.

The payroll data (salary, work schedule and so on) have to be entered into the system, and then these data can be sent to the accountant at the press of a button so that they can register the employee with the authorities.

10.4.6.2Source

The recruitment source master data records where the candidates come from (for example LinkedIn, referral, website, job fair). In the reports it is used for measuring channel efficiency.

Field Type Mandatory? Explanation / tips
Name of the source Text Yes For example LinkedIn, referral, website.
Active Switch Yes An inactive source does not appear on the “New candidate” form.

10.4.6.3Candidate status

The candidate statuses determine the steps of the recruitment pipeline (for example received, pre-screened, interview, offer, hired, rejected). You see these as columns in the Kanban view.

Field Type Mandatory? Explanation / tips
Name of the status Text Yes For example received, pre-screened, hired.
Active Switch Yes An inactive status does not appear on the Kanban.

10.4.6.4Interview type

The interview types (for example HR interview, technical interview, final interview) can be recorded as master data. In the reports they are used for measuring the interview load and efficiency.

Field Type Mandatory? Explanation / tips
Name of the type Text Yes For example HR, technical, final.
Active Switch Yes An inactive type cannot be selected for a new interview.

10.4.6.5Offer status

The offer statuses track the offer process: draft, sent, expired, accepted, rejected

Field Type Mandatory? Explanation / tips

Active Switch Yes An inactive type cannot be selected

10.4.6.6Onboarding templates

With the onboarding templates you can put together in advance who has to carry out which tasks when a new starter arrives. This way every hiring runs in a consistent, verifiable manner, and not a single step is left out (for example preparing the employment contract, procuring the equipment, granting the access rights).

A template consists of any number of tasks, which you can arrange into groups (for example IT, HR, Finance). Typically it is worth creating several templates, by job role — for example a separate template for office workers and a separate one for IT starters.

Adding tasks

After opening the template, you can add tasks with the Add new task button. For a task you specify the following

In the Group field you select which department or group the task belongs to. The Task name is the concrete task itself. The Type of responsible person is not a concrete person but a role (for example direct manager, IT officer) — this way the template remains reusable, and the system assigns the task to the appropriate person for every new starter. The Deadline type and the Number of days together give the relative deadline (for example “5 days before the start of work”), so you do not record a fixed date but a point in time relative to the start of work. If you tick the Mandatory task marker, the task cannot be skipped during the hiring. You finish adding the task with the Save button.
